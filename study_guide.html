The Question Bank (Nested Dictionary)

This is the "database" of the game — no external files needed to hold the questions.

A nested dictionary means a dictionary whose values are themselves other collections. In this project the layers are:

  • The outer dictionary — its keys are the two category names.
  • Each value is a list of questions.
  • Each question is a small dictionary with three keys: question, options, and answer.
QUESTION_BANK = {
    "Python Basics": [                      # a category (a list)
        {                                       # one question (a dictionary)
            "question": "Which keyword makes a function?",
            "options":  ["func", "def", "function", "define"],
            "answer":   "def"
        },
        # ...more questions...
    ],
    "General Knowledge": [ # ...second category...  ]
}

How the code reads it

Two loops walk through the structure — an outer loop for categories, an inner loop for the questions inside each one:

for category_name, questions in QUESTION_BANK.items():   # each category
    for question_data in questions:                     # each question in it
        ask_question(question_data, lifeline_available)

To read one value we use its key, e.g. question_data["answer"] gives "def".

💡

Why store the answer as text, not a number? We save "answer": "def" (the actual word) instead of "answer": 2. Checking is then just chosen_option == correct_answer — easy to read, and it never breaks even if the options are reordered.

The 50:50 Lifeline Logic

Remove two wrong options — but only once in the whole game.

Two ideas work together here: a flag that remembers if the lifeline is still available, and a helper function that builds the shorter list of options.

Step 1 — A flag remembers "used or not"

A single True/False variable, lifeline_available, starts as True. The moment the player uses it, we set it to False, so it can never be used again.

Step 2 — Build a shorter options list

The helper keeps the correct answer and adds just one wrong option — so two wrong ones disappear:

def use_fifty_fifty(options, correct_answer):
    reduced = [correct_answer]              # always keep the right one
    for option in options:
        if option != correct_answer and len(reduced) < 2:
            reduced.append(option)         # add ONE wrong option
    return reduced                         # list of 2 options

Step 3 — Only allow it when available

When the player types L, the code checks the flag first:

if user_input == "L":
    if lifeline_available:
        options = use_fifty_fifty(options, correct_answer)
        lifeline_available = False      # used up — lock it
    else:
        print("You have already used your 50:50!")
🔑

One sentence to remember: "A Boolean flag tracks whether the lifeline is still available, and a helper function returns a new list with only the correct answer plus one wrong option."

Questions Iian Might Ask (with answers)

Read these out loud once or twice — simple, confident answers.

Q1"Why did you break the program into so many functions instead of writing it all in one place?"
How to answer

"To keep it organised and reusable. Each function does one job — ask_question() asks a question, show_leaderboard() shows scores. It's easier to read, easier to fix, and I can test one part without breaking the rest."

Q2"What happens the very first time someone runs the game, before scores.txt exists?"
How to answer

"It won't crash. I used try / except FileNotFoundError around the file reading. If the file isn't there yet, the code catches that and just returns an empty list, so the leaderboard simply says 'No scores yet.'"

Q3"How does your code stop the game from crashing when a user types something invalid, like a letter or the number 9?"
How to answer

"I used a while True loop that keeps asking until the input is valid. I check .isdigit() to make sure it's a number, and then check it's between 1 and the number of options. Anything else prints 'Invalid input' and loops back — it never accepts bad data."
